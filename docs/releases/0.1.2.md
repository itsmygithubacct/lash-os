# lash-os 0.1.2

This corrective release fixes signal delivery during host I/O, preserves POSIX
record locks across exec, and closes a UNIX datagram socket-pair escape in the
confined QEMU. GNU Bash 5.3.15 and all 279 selected bash-os builtins continue to
run through the Linux eBPF JIT. The guest BPF image, pinned Linux 6.18.52 kernels,
and runtime dependency versions are unchanged from 0.1.1.

## Downloads and requirements

| Executable | Status | CPU requirement |
| --- | --- | --- |
| `lashos-0.1.2-linux-x86_64` | Primary tested target | x86_64 with hardware virtualization |
| `lashos-0.1.2-linux-aarch64` | Experimental | ARM64 with LSE atomics exposed through KVM |
| `lashos-0.1.2-linux-riscv64` | Experimental | RISC-V64 with Zacas exposed through KVM |

Hosted launches need Linux, access to `/dev/kvm`, Landlock ABI 6, and executable
private temporary storage outside the shared folder. Run as an ordinary user.
Verify downloads with the accompanying checksums:

```sh
sha256sum --check --ignore-missing SHA256SUMS
chmod +x lashos-0.1.2-linux-x86_64
./lashos-0.1.2-linux-x86_64 --version
```

`lashos-0.1.2-source.tar.zst` and `lashos-0.1.2-dependency-sources.tar.zst`
together provide the corresponding source and build recipes. See
[SOURCES.md](https://github.com/itsmygithubacct/lash-os/blob/v0.1.2/docs/SOURCES.md).

## Changes since 0.1.1

- **Signals and I/O:** pending guest signals interrupt blocking transfers and
  native syscall restarts. Nonblocking reads and writes return immediately with
  the native result. Signals preserve partial writes, and the loader leaves
  shared file status flags unchanged.
- **Exec and record locks:** read and write locks retain their ownership and
  ranges after exec failures and survive successful exec on retained
  descriptors. Failed exec attempts never briefly release locks to a competing
  process. Private loader handles close on successful exec.
- **Descriptors:** guest descriptors retain their native numbers. Loader setup
  and fork restoration reserve guest slots, temporarily increase the soft file
  descriptor limit within the existing hard limit, and restore it before guest
  execution. Failure paths release only loader reservations.
- **Sandbox:** the QEMU socket filter rejects UNIX datagram socket pairs, which
  could reconnect to named sockets. Connected stream and sequenced-packet pairs
  remain available.
- **Tests:** regression cases cover queued signals, native restarts, nonblocking
  I/O, partial writes, descriptor limits and cleanup, socket-pair types, and
  record locks across failed and successful exec on all three loader targets.

## Validation

All three static loaders passed nine host test groups each (27 group runs).
ARM64 and RISC-V64 host tests ran under QEMU user-mode emulation. Checks cover
the signal, nonblocking I/O, descriptor-limit, exec-lock and socket-pair
regressions, as well as the source and workspace tooling.

| Target | Verified for 0.1.2 | Remaining validation |
| --- | --- | --- |
| x86_64 | Native KVM: full builtin suite, registration of all 279 builtins, PTY job control, production guest initialization, shared home and networking, and all 18 production sandbox groups including confinement and cleanup | Coverage is limited to the documented cases and builtin feature subsets |
| ARM64 | Host tests under user-mode emulation; full-system emulated boot with raw syscall translation and registration of all 279 builtins | Native KVM, production launcher confinement, and complete process and terminal job tests |
| RISC-V64 | Host tests under user-mode emulation; full-system emulated boot with raw syscall translation and registration of all 279 builtins | Native KVM, production launcher confinement, and complete process and terminal job tests |

The executable inventories and test reports identify the checked artifacts by
SHA256. Release packaging verifies the pinned runtime, build-source content,
shared BPF image, kernel provenance and corresponding dependency sources.

## Boundaries

ARM64 and RISC-V64 remain experimental. Emulated tests do not certify native KVM
behavior or production launcher confinement on those hosts. Native plugins and
worker threads remain deferred. Forks load another verified BPF image and can
be slow. The shared folder retains the host user's permissions and has no
storage quota. Outbound networking can reach Internet, LAN and host services.
Direct mode on an unpatched host kernel can still encounter the BPF freeing
and vmalloc deadlock described in [patches/README.md](https://github.com/itsmygithubacct/lash-os/blob/v0.1.2/patches/README.md).
See [COMPATIBILITY.md](https://github.com/itsmygithubacct/lash-os/blob/v0.1.2/COMPATIBILITY.md) for the full boundaries.
