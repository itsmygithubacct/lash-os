# lash-os 0.1.1

A corrective release for 0.1.0. It fixes guest memory corruption caused by
mismatched guest and host structure layouts, tightens the sandboxed QEMU's
confinement, and hardens the build and release tooling. Its executables carry no
build-machine paths. GNU Bash 5.3.15 and all 279 selected bash-os builtins still
run through the Linux eBPF JIT, and each portable executable still contains its
own kernel, QEMU, guest tools, runtime libraries and firmware.

## Downloads and requirements

| Executable | Status | CPU requirement |
| --- | --- | --- |
| `lashos-0.1.1-linux-x86_64` | Primary tested target | x86_64 with hardware virtualization |
| `lashos-0.1.1-linux-aarch64` | Experimental | ARM64 with LSE atomics exposed through KVM |
| `lashos-0.1.1-linux-riscv64` | Experimental | RISC-V64 with Zacas exposed through KVM |

Hosted launches need Linux, access to `/dev/kvm`, Landlock ABI 6, and executable
temporary storage that the shared folder cannot reach, including through bind
mounts. Run as an ordinary user. Verify downloads with `SHA256SUMS`:

```sh
sha256sum --check --ignore-missing SHA256SUMS
chmod +x lashos-0.1.1-linux-x86_64
./lashos-0.1.1-linux-x86_64 --version
```

`lashos-0.1.1-source.tar.zst` and `lashos-0.1.1-dependency-sources.tar.zst`
together provide the corresponding sources and build recipes. See
[SOURCES.md](https://github.com/itsmygithubacct/lash-os/blob/v0.1.1/docs/SOURCES.md).

## Changes since 0.1.0

- **Guest memory safety:** `statvfs` and `fstatvfs` no longer overrun Bash's
  buffer (`df`, `lsblk`, SFTP). `realpath` no longer writes past a 1024-byte
  caller buffer (`stat`). On ARM64 and RISC-V64, `epoll_wait`, SysV semaphore
  status records and `timeval`-based calls now use the correct layout. Every
  structure still passed through unconverted is size-checked at build time.
- **Guest runtime:** signal handlers no longer re-enter for their own signal.
  `select` covers all 256 logical descriptors. Partial `munmap` and `mremap`
  work. `errno`, `sleep`, `statx`/`AT_*` flags and `posix_spawn` match glibc.
- **Sandbox:** the confined QEMU can no longer create UNIX or netlink sockets,
  and offline VMs can create no IP sockets or TCP connections. The private
  runtime directory is never placed on a noexec filesystem or where the launch
  folder can reach it through bind mounts. VM logs are bounded in memory, so a
  guest exit status of 125 prints no diagnostics. The caller's standard stream
  flags are never changed, termination signals during startup clean up, and
  `SIGTSTP`/`SIGCONT` are supported.
- **Loader:** arguments after `--` reach GNU Bash through both the outer and
  guest loaders, so `-- --version` reports the Bash version, and Bash can print
  version, help and error output before its normal stream setup.
- **Kernel:** the bundled Linux 6.18.52 kernels carry a defensive fix for a
  deadlock between BPF program freeing and vmalloc purging, which hung
  fork-heavy direct-mode tests on a 6.12 kernel. The deadlock did not reproduce
  on 6.18.52, so the fix is carried without a demonstrated reproduction. See
  [patches/README.md](https://github.com/itsmygithubacct/lash-os/blob/v0.1.1/patches/README.md).
- **Build and release:** source paths are remapped and inventories record
  workspace-relative labels, so executables and inventories no longer contain
  the build machine's directories. `make portable` publishes its build-host
  bundle separately from the pinned release artifact. Packaging refuses
  unpinned runtimes and executables built from anything but the release commit.

## Validation

Every executable was built from the release commit and records it. The three
static loaders each passed their eight host test groups, using user-mode
emulation for the cross-built targets.

| Target | Verified for 0.1.1 | Remaining validation |
| --- | --- | --- |
| x86_64 | Native KVM: all 18 production sandbox groups, including shared home, persistence, processes, networking, streams, terminal jobs, confinement and cleanup; production guest init, console, home and networking; and the full builtin and PTY job-control suite inside the artifact's own guest kernel | Coverage is limited to the documented test cases and builtin feature subsets |
| ARM64 | Host tests under user-mode emulation; full-system emulated boot of its own guest kernel with raw syscall translation and registration of all 279 builtins | Native KVM, production launcher confinement, and complete process and terminal job tests |
| RISC-V64 | Host tests under user-mode emulation; full-system emulated boot of its own guest kernel with raw syscall translation and registration of all 279 builtins | Native KVM, production launcher confinement, and complete process and terminal job tests |

Emulated results do not certify KVM behavior or the production launcher's host
confinement on physical ARM64 or RISC-V64 machines.

## Boundaries

Native plugins and worker threads remain deferred. Forks load another verified
BPF image and can be slow. The shared folder keeps the host user's permissions
and has no imposed storage quota. Outbound networking reaches Internet, LAN and
host services without filtering destinations. Direct mode on a host kernel
without the vmalloc fix can still hit the Linux deadlock described above. Read
[COMPATIBILITY.md](https://github.com/itsmygithubacct/lash-os/blob/v0.1.1/COMPATIBILITY.md)
for the full boundaries.
